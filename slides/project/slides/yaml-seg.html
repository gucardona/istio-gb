APÊNDICE: YAML DO ISTIO, SEGURANÇA

Três trechos de YAML no lugar do TLS no código

kind: Namespace
metadata:
  name: mesh
  labels: {istio-injection: enabled}

kind: PeerAuthentication
spec: {mtls: {mode: STRICT}}

Liga o proxy e exige mTLS

kind: AuthorizationPolicy
spec:
  selector: {app: catalog}
  action: ALLOW
  rules:
  - from: principals:
    [".../sa/frontend"]

Só o frontend chama o catalog

Estes são os pontos principais da configuração do Istio para segurança. Primeiro, o rótulo istio-injection no namespace: é ele que faz o Istio colocar o proxy em cada pod, sem mudar o deployment. Depois, a PeerAuthentication em modo STRICT: a partir dela, os serviços só aceitam conexões com TLS mútuo, e quem está fora da malha é recusado. O Istio cuida dos certificados e troca cada um a cada 24 horas. À direita, a AuthorizationPolicy: ela diz que o catalog só aceita chamadas da identidade do frontend, que é a service account dele. No caso B, isso tudo custou um arquivo Go de 46 linhas e um script para gerar certificados, sem renovação automática.
