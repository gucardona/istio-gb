ESTRATÉGIA: OS TRÊS CASOS

A mesma aplicação, montada de três formas

CASO A

Sem proteção

HTTP simples, sem criptografia e sem controle de acesso. É a nossa referência de velocidade.

CASO B

Proteção no código

Nós mesmos programamos em Go o que o Istio faz: criptografia, permissões, tempo limite, nova tentativa e métricas.

CASO C

Istio

O código volta a ser simples, e o Istio cuida de tudo isso por fora, através dos proxies.

Com o caso B dá para separar o custo das funções (criptografia, tempo limite, nova tentativa) do custo dos proxies do Istio.

Para comparar de forma justa, montamos três versões. O caso A não tem proteção nenhuma: é o mais rápido, mas qualquer um entra. O caso B tem as mesmas funções do Istio, só que programadas por nós em Go. O caso C usa o código simples e deixa o Istio fazer o trabalho. Se a gente comparasse o Istio só com o caso A, ia parecer que ele é caro à toa, porque ele faz muito mais coisa. Com o caso B no meio, dá para ver quanto custa cada função e quanto custa o Istio. Os três usam a mesma imagem, as mesmas máquinas e a mesma carga.
